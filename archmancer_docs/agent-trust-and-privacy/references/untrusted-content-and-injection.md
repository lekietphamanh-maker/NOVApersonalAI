# Untrusted content and injection

Read this leaf only when a model can encounter caller-supplied, retrieved, remembered, delegated or tool-returned material that may contain instructions. A model processes instructions and data together, so provenance helps interpretation but cannot confer authority. The [trust and privacy chapter](trust-and-privacy.md) owns the threat model, and the [action boundary](../../agent-harness-model-and-tools/references/action-and-tool-boundary.md) owns enforcement of effects.

## Mechanism and failure

Record the producer and origin of each lower-trust item through ingestion, retrieval, summaries, memory and child reports. Present the material as evidence with its origin and delimiters, while treating its content and any embedded role or system claims as untrusted. Construct trusted roles and framework metadata at the host boundary, not from content submitted by a caller or returned by a tool. If a source can contain delimiter-shaped text, neutralize it at the embedding point and test the actual composed request, including split fragments and unsupported content types. Delimiters reduce ambiguity; they do not turn instructions in the data into authority.

On a request, the harness may read a document and propose a tool call. The executor independently checks the caller's grant, the resolved target and executable prerequisites. If the document asks the model to override those constraints, the content remains evidence and the unauthorized action is rejected. If a search fails, preserve the unavailable or partial state; do not convert it into an authoritative no-match. Consult [evidence and knowledge access](../../agent-evidence-and-knowledge/references/evidence-and-knowledge-access.md) for grounding and [context and state management](../../agent-context-and-state/references/context-and-state-management.md) for provenance and persistence.

For structured tool results, reserve framework-owned metadata separately from tool-provided fields. If an untrusted result contains a reserved name, nest or reject that field at ingress under the chosen contract; a decorator that only resolves collisions with fields it adds on this invocation leaves other forged names possible. Record producer identity structurally, not by a self-asserted text tag. Where child reports use an envelope, escape closing and opening fence forms and attribute values at the child-notification builder before truncating, then make omissions explicit. A fence escaped there does not imply the same tag is reserved on every other input path. A child report is a self-report: verify external side effects with the owner.

## Decisions by pressure

| Premise | Minimal mechanism | Extended option and pressure |
|---|---|---|
| The agent reads no untrusted material | Keep trusted input boundaries explicit | No injection detector is required merely because a model is present. |
| Untrusted material can enter context | Preserve provenance; enforce authority and effect rules outside the model | Add tailored source isolation and output controls where the threat model identifies a remaining exposure. |
| A detector can provide useful evidence | Record a typed, scoped signal and its failure state | Add calibrated screening only with measured benefit, error costs, latency and a defined response. |
| A class of action must be forbidden or independently approved | Enforce the policy at the action owner | Add a hard detector gate only where a separately approved policy establishes its role and fallback; a probabilistic score does not replace the deterministic gate. |
| Content may persist or reappear | Preserve source lineage and limit what may become a durable instruction | Add provenance-aware extraction and review where memory or summary poisoning is a credible path. |

## Injection paths and counterfactuals

- **Premise:** retrieved or tool-returned text contains an instruction. **Symptom:** the model treats a document as a new operator. **Cause and evidence:** the source's text and the model's instruction stream share a context; this is a threat-model failure mode, not proof that every model obeys. **Rule:** retain source identity and enforce allowed actions independently. **Check:** return a genuine source containing a forged instruction and verify both the attempted action and protected state; a positive control proves the tool can reach the effect. **Does not apply when:** there is no untrusted source and no model-visible lower-trust text.
- **Premise:** framework text is enclosed by markers. **Symptom:** a source forges a closing marker and impersonates another role. **Cause and evidence:** a delimiter is syntax unless its inner payload is escaped; proposed hardening requires verification on the actual composition path. **Rule:** neutralize reserved marker forms where payloads enter the envelope. **Check:** inspect the final request with forged opening and closing markers, attribute values and fragments; removing the sanitizer should make the deterministic fixture fail. **Does not apply when:** there is no delimiter-based envelope.
- **Premise:** an envelope declaration and escaping serve several purposes. **Symptom:** a team removes the declaration after a test on an unrelated behavior shows no difference. **Cause and evidence:** that measurement did not isolate marker forgery; the declaration's independent behavioral benefit was not established. **Rule:** list each purpose before changing either mechanism and measure the relevant behavior. **Check:** use actual ingress and an otherwise identical request with and without the declaration; no observed difference is inconclusive, while a deterministic fixture with the relevant escaper removed must reveal its literal boundary. **Does not apply when:** there is no such declaration or untrusted content sharing its carrier.
- **Premise:** memory or a summary persists derived content. **Symptom:** an earlier instruction from an external source returns later as apparent guidance. **Cause and evidence:** a lossy transformation can remove origin and promote data into instruction. **Rule:** preserve origin and apply admissibility at capture and recall; a generated summary does not gain authority. **Check:** use a real ingestion-to-recall path and confirm the injected instruction cannot authorize an effect. **Does not apply when:** no content persists across calls.
- **Premise:** a sensitive write has prerequisites. **Symptom:** an attack appears resisted because the model did not call the tool. **Cause and evidence:** a non-call never exercised the enforcement path. **Rule:** distinguish model behavior from the gate that would reject a call. **Check:** force an equivalent unauthorized proposal and inspect the effect, then exercise an authorized positive control with prerequisites met. **Does not apply when:** no action or protected effect exists.
- **Premise:** a client-supplied carrier can change a protected state. **Symptom:** an asserted completion causes a transition without the underlying event. **Cause and evidence:** trusting a client marker can authorize an unsupported transition; removal of such a path must be verified. **Rule:** delete the carrier when genuinely unused, or validate a needed one against an authoritative record. **Check:** start in the reachable prerequisite state, submit a forged carrier and verify unchanged state; use a valid transition as a positive control. **Does not apply when:** no untrusted carrier can change state.

## Detection as a measured signal

Choose screening only for a stated threat and operational decision. Specify its input eligibility, typed result, invalid or incomplete output, deadline, privacy treatment, cancellation and failure response. A timeout, refusal, malformed response or unavailable service is unassessed, not a zero-risk result. A signal can inform review, logging or model context without authorizing an action. If a policy chooses blocking, specify ownership, measured false-flag and miss costs, fallback and independent hard controls; do not infer safety from a score alone. Maintain data minimization for prompts, logs, traces and retained signals under [sensitive-data lifecycle](sensitive-data-lifecycle.md).

If screening is selected, define which newly admitted content it assesses and its producer; do not silently substitute an earlier message when the intended input is ineligible. Bound inputs and represent oversize, missing context and partial assessment explicitly. A partial result may preserve assessed hazard signals while marking an unassessed dimension; a failed assessment carries a reason rather than fabricated probabilities. Validate response question identities and types, configured model identity, finite probabilities in range and nonnegative integer usage before using any flag. Select thresholds on labelled data and name the cost of misses and benign flags. Separate moderation and injection questions when their policy owners differ; combine only by an explicit decision.

When a warning accompanies a turn, bind it to the assessed message and deliver it before the model step it informs. Distinguish rendering from durable persistence: only a successful turn write makes the warning replayable, and a retry may reassess and incur another charge. Verify the effective enablement and credentials for every applicable configuration and execution path; keep the trusted policy and the per-turn signal in their intended positions in the composed request. Independent optional checks may run concurrently only with separate failure policies. Mandatory privacy admission must fail the affected request when protection cannot be established; advisory failure can return unassessed for an already admitted turn, but must not send unprotected data. External cancellation propagates without a completed assessment or observer notification.

A cooperative detector deadline bounds only the awaited assessment, not synchronous callbacks, logging, assembly or surrounding admissions. Keep an observer to bounded enqueue work, measure total pre-model latency separately, and retain an independent host deadline. Record content-free completed-screen events with reasons, and count attempts and cancellations from the host as well; a completed-event log is not a complete attempt ledger. Check adjacent executions, early exits and cancellation for leaked run-local context. A warning's delivery does not establish its independent benefit: compare with a suitable control under a frozen policy, and treat ceiling results, contested labels or unexercised actions as inconclusive.

Before evaluating a detector or prompt-level defense, freeze the scenario distribution, attacks, benign cases, outcomes, error and latency requirements, uncertainty treatment, spending and stop conditions. Test real ingress producers rather than pasted imitations: applicable tool returns, retrieval, persisted memory, continuation and child reports. Check protected-text disclosure, forged instructions, unauthorized effects, controlled-destination exfiltration and marker forgery where applicable. Include benign hard negatives and positive controls. Validate the oracle against known compliant and refusing outputs; inspect state before and after the attempted effect. Record unsupported ingress as not applicable with the actual reason. An unexercised gate, incomplete terminal outcome or unverified state makes the relevant result inconclusive.

Track source-proven gates, exercised rejections and model non-calls separately. Test both unmet and met prerequisites and use actual state reads to establish whether a write was reachable. Validate text oracles on planted compliant and refusing replies, account for negation and paraphrase, compare stable business state instead of volatile fields, and rescore saved raw events if an oracle changes. A missing terminal event or failed status read is inconclusive. Test real indirect producers rather than claiming them covered by chat imitations. Include a deliberately flagged benign case and preserve legitimate service or justified clarification as a measured outcome. These checks are a proposed verification design, not a claim of a completed assessment.

System-role handling can differ by provider route and model capability; deployment behavior requires verification. Inspect the actual effective request before relying on message order or role placement. Attribution text can change obedience in either direction; its effect and provider ranking require qualification. Recalibrate any detector after changing provider, model, client or route: a measured regression on a different task does not establish this task's outcome. A structured-output fallback is a candidate requiring its own validation, not an already qualified adapter; warning cache impact was not measured.

## Build, debug and optimize

1. **Build:** map every ingress to its producer, trust level and eventual action or output; check that forged role metadata remains data and the real executor rejects an unauthorized effect.
2. **Debug:** capture a privacy-safe account of the actual composed request, detector status, proposed action and effect-owner decision. A detector flag without a corresponding input or a non-call without an exercised gate cannot explain the outcome.
3. **Optimize:** compare detector or prompt changes under a frozen policy on representative attacks and benign tasks. Report observed gains and losses, unassessed cases and hard-gate failures separately. Omit a detector whose added complexity has no supported value under the declared threat model.

## Worked example — one implementation under stated premises

Premises: an assistant summarizes files and can submit edits after approval. An external file says to reveal protected text and perform an edit. The context renderer identifies the file as source data; the model may summarize it but cannot grant itself permission. The action boundary checks the user's actual scope and the exact approval independently. A test invokes the protected action directly with a forged approval, verifies no mutation, then uses a legitimate approval as a positive control.
