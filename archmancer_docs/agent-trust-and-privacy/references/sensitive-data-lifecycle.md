# Sensitive data lifecycle

Read this leaf only when personal data, credentials, or other sensitive data can enter, be derived by, or leave the system. Name the data owner, protected categories, threat, allowed uses, retention and erasure promise before choosing controls. The [trust and privacy chapter](trust-and-privacy.md) owns the cross-cutting threat model; [authority and approval](authority-and-approval.md) owns authorization; [context and state management](../../agent-context-and-state/references/context-and-state-management.md) owns persistence and continuity semantics. A single process or store does not remove these boundaries. For concurrent deletion and recovery, read [erasure and forget](erasure-and-forget.md).

## 1. Inventory and minimum contract

If request payloads are retained, omit transport credentials and headers from the saved payload and separately protect the remaining values under their actual classification. A scan for credential-shaped keys does not prove arbitrary text values contain no secrets. Distinguish non-secret configuration descriptors from secret-bearing credential transport and authorize each disclosure independently. Plant a secret in free text and a transport header, then inspect the persisted representation and every recipient; neither a key-only scan nor descriptor access authorizes secret export.

If pseudonyms or references are used for correlation, equality is only a hint within their declared authorized scope and lifetime; it is not a global identity or an authorization proof. Check different scopes, rotation and identity merge before joining records.

When privacy protection refuses a request, return stable machine-readable categories alongside safe, value-free text so callers can distinguish a privacy refusal from an unrelated failure without seeing sensitive data. Audit upstream business error bodies and chained exception causes as rendered to clients and logs; inject synthetic secrets and verify no renderer exposes them.

Map each source, transformation, recipient, storage location, access authority, retention, deletion owner and proof of removal. Include user inputs, attachments and keys; configuration and tool declarations; model requests, responses and reasoning; tool arguments, results, artifacts and callbacks; delegation; histories, checkpoints, summaries, titles, memory and embeddings; prompt and application caches; queues, streams and replay; logs, exception messages, traces, usage and accounting; provider and third-party stores, backups, client copies and exports. Identify both content and metadata, including subject identifiers, property names, numeric values and encoded JSON. Record unknown or unavailable stores as unknown, not absent. Treat a reference, digest or tombstone as potentially linkable data, not automatically anonymous.

Minimize collection and transmission at each producer before persistence, observation or external send. If sensitive data is unnecessary, omit it; if a recipient needs a subset, project just that subset. Establish purpose, authorized principal, resource, operation and version, and the failure outcome before releasing a value. Install controls before enabling any writer or sink they protect, and verify the effective runtime configuration rather than a configuration file alone. Fixed, value-free errors and safe logging reduce accidental disclosure; inspect exception rendering, tracebacks, test-runner locals and client errors as well as ordinary logs.

A normal path is: classify and admit the input; apply the selected minimization before the first write or model call; allow only authorized, purpose-limited use; protect derived and replayed copies; then expire or erase all covered copies under the declared policy. If an admission control or required protection is unavailable, fail closed before the protected write or send; an unavailable check is not evidence that data is clean. If a result is withheld after a tool executed, report that separately from not run or execution failure. Follow [action and tool boundary](../../agent-harness-model-and-tools/references/action-and-tool-boundary.md) and [durable execution and recovery](../../agent-runtime-and-interaction/references/durable-execution-and-recovery.md) for uncertain effects: reconcile before retry; allow verified idempotent replay; otherwise stop for manual reconciliation.

## 2. Choose controls for the actual pressure

| Premise or pressure | Minimal choice | Additional mechanism and cost |
|---|---|---|
| No sensitive input or derived data | Exclude it at admission and confirm carriers | Revisit when a source or recipient changes |
| A recipient does not need a value | Omit or project fields before that boundary | Add redaction for unavoidable free text; detection has coverage and false-positive limits |
| Sensitive data must be retained | Restrict access and set purpose, lifetime and deletion owner | Encrypt and manage keys as needed by the threat model; encryption does not remove access or retention obligations |
| Selected raw values must be kept from a model or sink but used later | Use a protected reference only if its lifecycle and reconstruction are necessary | A mapping vault adds authorization, availability, linkability, merge and deletion coordination; it is not a default |
| Data may be erased during active work | Stop admission and fence all participating writers until deletion is established | Durable deletion state and recovery are needed when the fence or process can fail; unsupported quiescence means incomplete |
| A provider offers retention controls | Verify effective account, route and setting against the promise | Provider controls do not erase platform, client or third-party copies |

These are conditional design choices, not a universal vault architecture. Separately record policy choices and the evidence supporting each guarantee; a detector that covers certain formats does not establish all-input confidentiality.

Retention can support continuity, permitted replay and diagnosis, but every retained body, derivative or linkable marker increases exposure and the work needed to erase it. This recorded design judgment favours purpose-limited collection and the shortest retention compatible with the required use, without inventing a universal lifetime. Define immediate loss of serving access, logical withdrawal, physical purge and complete erasure as separate promises; withdrawal can be quick while purge remains pending, and complete erasure may need recoverable progress and writer fences. Acknowledge only the state verified across the declared copies and writers; retained audit or external copies remain explicit limitations.

## 3. Detection, references and exposure boundaries

When handlers are initialized, normalized or replaced, preserve required safety filters on every effective handler before exporting records, including startup and replacement paths. A filter attached only to a removed handler leaves subsequent records exposed. Send synthetic secrets through the actual startup and handler-replacement sequence, inspect all surviving sinks and treat any earlier unobserved interval as unverified.

If unsupported carriers are recognized by field names or part types, document the exact recognized names and types and the resulting refusal or protection policy. Such a filter is not a general URL or opaque-input detector: a URL in ordinary text or an unfamiliar field can bypass it. Test recognized fields, ordinary text URLs, unknown parts and nested carriers; report the uncovered domain instead of claiming complete detection.

**If automated identification is selected**, specify categories, languages, formats, typed fields, input shapes and exclusions. Use typed registration or rules appropriate to the domain, and qualify their false positives and misses with representative labeled data; finite golden vectors and sentinel captures do not measure population recall. An observed sentinel-free log sample does not establish unobserved providers, categories or trace sinks. Check mapping keys, nested values, numbers, decoded JSON, model output, multimodal content and cross-message reconstruction independently. For an unscannable carrier, refuse it or explicitly accept the exposure; a clean text scan does not cover a file or encoded representation. Record historical data and already-exported copies separately from new admissions.

For protected references, tool restoration, streaming and narrowly scoped exemptions, read [protected references and admission](protected-references-and-admission.md).

**If a redaction sink is enabled**, state exactly which fields, keys, numbers, nested encodings, attachment shapes and retained subject identifiers it handles. A pattern-only redactor cannot recognize every registered value; a trace processor is not a logger, and an untraced region does not prevent explicit logs. Install protection before export and verify ordering and the effective configuration. If a sink derives accounting identifiers after initial projection, protect the final payload too; preserve necessary bound identity only as declared retained data.

**If debugging handles credentials**, use a value-silent authorized source, mock credentialed clients when possible, and inspect exception renderers, test-runner locals and client echo paths. A masked wrapper reduces accidental display only while the value stays wrapped. If exposure is found, quarantine the artifact and recommend rotation by credential name; do not reproduce the value in the report or pass raw credentials through tool parameters that can echo them.

## 4. Erasure

If deletion is promised, use [erasure and forget](erasure-and-forget.md) for the subject fence, writer coordination, recoverable deletion and verification. Retention of mappings and the exposure inventory remain here.

## 5. Causal lessons and provider deltas

**Premise:** a free-text scanner claims exclusion across all carriers. **Symptom:** an identifier remains in a dictionary key or number. **Cause and evidence status:** a producer scanning only string values can miss other shapes; another collector does not establish its coverage. **Rule and reason:** inventory and protect each carrier at its actual producer because sibling coverage does not transfer. **Check and expected evidence:** send synthetic identifiers in keys, numbers, nested encoded text and results through each producer; each is protected or explicitly refused, and any unobserved sink is not established. **Does not apply when:** those shapes are provably excluded before admission.

**Premise:** raw detection applies to fixed declarations. **Symptom:** valid calls are refused by identifier-like schema literals. **Cause and evidence status:** a detector applied to trusted declaration literals can match examples or numeric bounds; occurrence and frequency on the selected route require verification. **Rule and reason:** distinguish trusted fixed configuration from customer content with narrowly evidenced exemptions; keep protocol and reference checks. **Check and expected evidence:** a declared benign literal passes only in the proven position; the same value in customer content is protected or refused. **Does not apply when:** declarations cannot carry such literals or are themselves sensitive.

| Provider | Account and route retention evidence | Qualification |
|---|---|---|
| Anthropic | Account and route retention unmeasured | Verify current agreement, actual setting, cache and abuse-monitoring terms for the exact deployment; otherwise mark unverified. |
| OpenAI | Account and route retention unmeasured | Verify the same conditions for the exact model, API and account; do not infer them from a client option alone. |
| Gemini | Account and route retention unmeasured | Verify the exact product, deployment and account terms; a different hosting route may have different handling. |

A provider-side setting alone does not establish recall of sent content or erasure of local copies. Provider differences must be verified from current account-specific evidence; these are unmeasured categories, not claims of equal policies.

## 6. Build, debug and optimize checks

- **If any sensitive data is in scope:** freeze categories, threat, permitted exposures, carrier and sink census, owners and expected evidence. Activate each producer or sink only after its own control is verified. A missing capture is not a pass; distinguish harness faults from product faults and use failing controls that include short numeric scalars. Stop an affected invalid measurement rather than retrying until it passes.
- **If detection is used:** exercise positive, negative, overlap, Unicode, split and encoded cases, keys and numeric leaves, with a failing control for each scanner and each supported producer. Record false positives and unmeasured coverage; compare actual sink contents, not just a successful response.
- **If a vault is used:** check cross-subject and wrong-kind denial, collision exhaustion, erased versus unknown references, escaping, concurrent registrations, stale proof and unavailable vault. Test mapping expiry against every dependent artifact and identity-merge interruption; no foreign resolution or premature expiry passes.
- **If streaming or restoration is used:** split a reference at every character across supported text and tool channels; check malformed, escaped, cancelled and unsupported envelopes, authorization and JSON encoding. Verify a deletion between frames does not release stale cached values; acknowledge the non-atomic delivery window.
- **If optimizing scanning or caches:** measure the selected workload and memory costs without weakening the protected-carrier contract. Version cached clean verdicts with detection rules; a digest collision or a pre-filter missing a rule cannot prove universal cleanliness. Validate all copies with shared vectors and differential cases; ship rule changes across the active copies together and invalidate affected verdict caches.

**If privacy acceptance is evaluated**, freeze protected categories, carrier-by-carrier exclusions, captures, metrics and stop conditions before seeing outcomes. Use synthetic sentinel values in text, keys, numbers and encoded text at every producer and inspect each actual sink; an unexpected raw hit or foreign reference fails. Repeat the same census for unavailability, stale repair, malformed references, retries, cancellation and worker failure. Missing captures or invalid oracles make the affected result incomplete; retain evidence and continue independent valid checks. Do not reinterpret an exposure after observing it.

**If activating protection**, record each writer and sink, its owner, prerequisite and first-enable evidence; check that bypassing a prerequisite leaves that consumer disabled. Until then use synthetic data and controlled sinks. Inspect runtime callback order and a deliberate refusal on the same process; a configuration file is not activation proof. Record the owner-approved protection contract and carrier-specific exposure register, including explicit owner sign-off.

If qualifying an enabled route with synthetic data, capture its provider request and each actual sink; inspect client replies, protected copies and cross-subject denial. Log scans alone cannot establish an unobserved provider request or unavailable trace sink. Check credential renderers and tool listings for exposure, and record a reviewable coverage and exposure report for the data owner.

## 7. Worked example — one implementation under stated premises

Premises: a document assistant stores conversation history, sends text to an external model, and must later forget a named subject; an authorized tool occasionally needs the original contact value. The owner excludes raw contact values from model calls and logs but explicitly lists provider copies and backups as outside immediate deletion. Admission replaces the declared contact field with an opaque subject-scoped reference before storing or sending; the executor resolves it only for the authorized tool, while summaries and traces retain the reference or omit it. The mapping stays while history needs it. A forget request fences new and in-flight writes, removes the history and mapping, and returns incomplete if a writer or covered store cannot be reconciled. This example does not establish coverage of untyped free text or provider retention; those require their own detection and account evidence.
