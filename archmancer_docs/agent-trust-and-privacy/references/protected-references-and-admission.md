# Protected references and admission

Read this leaf only when a threat model requires keeping selected sensitive values from a model or other recipient while retaining the ability to use them later. The [sensitive data lifecycle](sensitive-data-lifecycle.md) owns the inventory, minimization and retention premise; [erasure and forget](erasure-and-forget.md) owns concurrent erasure.

## 1. Admission, references and use

When mappings are encrypted at rest, authenticate subject, owning scope, token and kind as associated context so ciphertext cannot be moved between records undetected. Define consistent live and erased states: live records retain the required encrypted value and lookup material; erased records cannot recover it and retain only policy-permitted markers. Specify one canonical encoding and version for every reader and writer, with compatibility checks during migration. Substitute each associated field, construct inconsistent state and round-trip across versions; reject tampering or unsupported versions without releasing a value.

**If references are selected**, instruct the model to copy a whole reference without inventing or splitting it, and qualify that behavior on each enabled model; a prompt is not proof of compliance. Define an unambiguous grammar, escaping, type and ownership checks, and an opaque non-recycled token; reject collisions rather than merge values. Treat caller-supplied reference-shaped text as untrusted. A reference is usable only for the authorized principal, subject, kind and purpose; the same organizational scope alone is insufficient. Distinguish an owned erased reference from an unknown, foreign or wrong-kind reference without disclosing another subject's data. Protect mappings and keys; a deterministic value-derived hash can enable guessing and does not itself provide erasure. Reuse stable references when continuity requires it, without treating unequal references as proof of unequal values after an identity merge.

For each producer, record representation and mode: raw inputs are admitted; model-written continuations, memory candidates and summaries validate references; recall queries and job inputs use the mode appropriate to their carrier. Stored legacy text can be neutralized in a protected read copy, but only if that read actually invokes admission; without the hook the old raw value remains exposed.

If the chosen policy intends recoverable raw values to persist only in the mapping store, make that a conditional target across every participating producer and sink; old raw records, exempt content and reconstructed model output remain separate exposures until independently covered.

For a protected-reference design, define raw admission separately from validation of already protected, model-written text: reject forged, foreign, malformed or erased references in validation, and escape literal reference-shaped input on raw admission. Process existing protected segments structurally so repeating admission cannot turn escaped text into a live reference. If typed values are registered, register the batch before masking free text so field order does not leave another mention raw. For legacy rows choose neutralization, migration or refusal explicitly; reading a protected copy does not erase the original.

Retain a mapping for at least as long as any retained artifact needs it, or delete/rebuild all dependent artifacts before expiry. Erasure removes the recoverable value and lookup material under the chosen policy, while any retained no-recycle marker and its linkability remain in the inventory. If identity aliases can merge, preserve old references and coordinate the mapping move with identity state; an interrupted cross-store merge needs a durable pending marker, stable operation identity, same-target recovery and rejection of conflicting targets. A split store needs a stable operation identity, alias snapshot, pending marker, fence owner, idempotent remote steps, completion receipt and recovery owner; interrupt before and after each remote commit rather than assuming remote calls are atomic.

**If admission proofs or hydrated values are cached**, bind them to the subject and generation of the protected data; invalidate or revalidate when registration, merge or deletion changes that generation. For a snapshot assembled from several reads, its proof cannot be newer than its oldest input. A generation probe can itself race a later update, so define the required consistency and do not imply instantaneous revocation. A cached membership proof does not establish that a token remains live after erasure. If freshness cannot be established, rebuild within a bounded policy or refuse the send. If streaming is used, qualify each supported provider envelope and channel; buffer incomplete references and reject unsupported or malformed shapes. Reference-integrity buffering alone does not detect raw reconstructed output, and already delivered bytes cannot be recalled.

Caching a verified admission or authorization proof can save dependency calls and caller waiting time, but trades freshness for reuse and adds invalidation and generation-race handling; checking every use instead pays dependency latency and availability cost. This is a recorded design judgment, not a measured speedup. Select an explicit permitted staleness policy before caching, bind reuse to the owning subject and version or generation, and revalidate or refuse when the required freshness cannot be established; a cached proof is not instantaneous revocation.

**If delegated work carries protected text**, apply the same admission and subject scope to the child brief; do not hydrate it merely to delegate. A child-creation writer must participate in the forget fence, including the race between the last check and commit.

**If tool execution needs the original value**, resolve only inside an authorized execution copy, validate the resolved value against the business schema, and avoid exposing it to callbacks, traces or error renderers. The model-facing schema must accept the reference without silently weakening the actual business validation. Cover nested schema alternatives, arrays, numeric forms, result artifacts and state updates; refuse an unsupported shape rather than claim complete projection. A result may have been committed before its privacy check fails.

**If request repair is used**, scan all covered request carriers after producer admission, repair a protected copy and rescan it, then send that returned copy. Refuse values that cannot be repaired without breaking protocol types, immutable routing fields or unsupported opaque content. Fixed configuration is exempt only under a proven narrow policy; reference validation remains in force. Repair is a backstop, not a substitute for admission before storage or callbacks.

**If an exemption is necessary**, define its exact data, path, trusted provenance and recipient. Bind server-validated evidence to the actual principal, resource, operation, version, request and carrier as applicable; fail back to normal protection if a condition is absent or changes. An exemption for public material does not cover customer questions or all content from the same credential. Third-party handling belongs in the exposure register, not an assumed exemption. Inspect both positive and neighboring negative cases, including reused or substituted proof.

## 2. Conditional mechanisms and counterexamples

On a privacy-scoped path, keep raw request bodies out of logs on success and failure, including exception paths; record only safe structural diagnostics. Send synthetic sensitive values through an admission failure and inspect every effective log sink; the raw body must not appear.

When reading protected state, distinguish an absent field from an absent container when the authorized API exposes that distinction, and distinguish both from unavailable authorization or hydration. On unavailable or mismatched authority, withhold the protected value and return the safe policy-defined outcome; do not manufacture absence or disclose existence beyond the chosen policy. Check each absence and dependency outage with an authorized positive control.

When tool results contain structured JSON as text, decode, admit all covered values and re-encode the protected structure; reject malformed or ambiguous input. Validate reserved ownership metadata against trusted execution identity rather than accepting the tool's assertion. Admit execution-body output and errors before callbacks observe them, then re-admit additions from hooks or decorators. Declare sensitive result-field kinds for downstream guards and separately inventory nested inputs and outputs outside top-level declarations. On failure withhold the unit and return a safe error correlated to its invocation, without claiming the effect did not happen. Check encoded values, forged owner markers, nested fields, body errors and post-hook additions at callbacks and public output.

If privacy scope varies by run, derive it from trusted persisted identity and authenticated authority, not caller-provided lane flags; a missing subject on a protected run is a construction failure, not a silent bypass. Install and clear task-local scope around each asynchronous step and cleanup rather than across a generator yield, because the consumer can otherwise inherit it. Check concurrent scopes, cancellation and early exit.

If a fixed configuration is protected once and reused, enumerate every model-facing slot and record excluded structural fields. Version the selected raw slots and scope any cached protected copy to that version and subject domain; if a shared public namespace is warranted for trusted configuration, restrict its writer and prohibit it from authorizing access to any subject namespace; separately fingerprint the materialized executable form. A privacy version and an executable fingerprint answer different questions. Check a changed slot, another subject and an omitted slot independently.

If a protected operation uses an in-process scope, keep the highest observed generation; refresh it from authoritative responses or a current probe. Tie proofs to that generation and to their scan mode, because a proof for exempt content cannot justify a checked occurrence. A synchronous route unable to establish freshness or validate references must refuse the protected call. For snapshots assembled by separate admissions use the minimum input generation; on stale proof re-admit a copy or fail within a bounded retry policy.

For a batched admission collector, gather a detached copy, derive the subject from trusted owning state, require the returned result count to match the collected carriers, apply every reconstruction before persistence, and fail closed when required protection is unavailable. Reject ambiguous duplicate-key JSON, and classify customer-bearing variable keys rather than silently treating them as routing keys.

For tool inputs, project sensitive typed fields before callbacks or events observe them. For tool results, cover content, artifacts, metadata, state updates, continuation values and delegated arguments after every producing or decorating layer; preserve routing structure, refuse unknown shapes and withhold the whole unit on admission failure. If an execution hook is used, validate declarations and conflicting types at activation and check that the hook is actually active on each protected path; inspect published tool descriptions and schemas for sensitive examples; registration of values alone neither masks output nor reverses a completed effect. Test nested and nullable arrays, schema alternatives, numeric forms and customer-bearing keys in errors.

If model-visible schema differs from a business schema, validate the model-facing shape first, resolve only in the authorized executor, then apply the original business rules. For value-bearing failures use fixed codes and structural paths rather than echoing input or sensitive property names; a renderer protecting only hydrated leaves can leak other values, so a universally value-free renderer is a proposed requirement, not a verified fix. A model reference definition helps communicate the intended use, but model compliance is route-dependent and unverified; qualify each route.

If restoring a reference for an authorized caller, verify subject, principal and purpose, recheck cached mappings after a generation change, encode values for their output format and prevent caching when the response contains restored values. If restoration fails, withhold the affected output and report a fixed safe failure with neither the underlying value nor the reference; already delivered frames cannot be recalled. A missing authorization or subject match must not yield a restored value, and an erased-value sentinel must not be passed as a business argument.

For a model-bound backstop, inspect decoded content before encoding and inspect the final body as well. A syntax check for references is not an ownership check. Scan protocol values without rewriting immutable identifiers; refuse an unsupported opaque shape or an unmaskable number when required protection cannot be established. Exempt only a proven fixed subtree, retain reference checks there, and re-run protection on caller-derived accounting fields built after earlier hooks. A service credential alone is insufficient to exempt a different operation or customer question.

If a verifier depends on state shared by callbacks, test it through the actual loader: separate module instances can prevent one callback seeing another’s proof even when isolated tests pass. Keep proof state in a shared importable owner or equivalent, and check wrong request, carrier, call type, principal, origin and reused proof. This proposed qualification does not establish behavior of the selected deployment.

If reference-bearing output is streamed, track each text, reasoning and tool-argument channel independently; hold only a possible incomplete reference suffix, reject malformed reserved forms and flush or discard according to completion or cancellation. Test every provider-adapter envelope, including the unknown-envelope path; a text-only hold neither detects raw reconstructed output nor establishes coverage for every SDK shape. Complete stored frames and previews need an explicit boundary check. Normal-path prefix handling does not establish all-branch safe previews. Exercise malformed-reference parsing failures and inspect the effective output before claiming error-path coverage.

**Premise:** masking is centralized at a gateway but some paths bypass it or execution needs original values. **Symptom:** an unsupported protocol cannot be protected or restoration reaches the wrong boundary. **Cause and evidence status:** recorded design judgment: gateway-only masking and reversal are insufficient when a route bypasses that boundary or authorized restoration belongs to a different execution owner. Route-specific adapters and restoration ownership require explicit contracts; this judgment is not evidence that a particular implementation has complete coverage. **Rule and reason:** protect at each producer before durable storage and observations; add a separate refuse-only backstop when all relevant routes can be checked. **Check and expected evidence:** inject a synthetic value through every producer and unsupported route; it is protected before observation or the route is refused. **Does not apply when:** a proven single boundary handles every carrier and authorized restoration under its own contracts.

Stable reference bytes can support a stable prefix, but other context changes can alter it; compare the provider-effective request rather than infer a cache hit. If a protection service is temporarily unavailable, fail closed before protected storage or sending; preserve the authenticated session and return a safe availability outcome; retry only under the effect owner’s replay contract. Treat restart-based causal explanations and proposed rollout or retry changes as unverified hypotheses until failure-path evidence establishes the cause and a bounded check verifies recovery; any retry remains subject to the effect owner's replay contract.

## 3. Provider and client qualification

| Concern | Anthropic | OpenAI | Gemini |
|---|---|---|---|
| Streaming | Qualify text and thinking blocks and partial tool JSON; a normalized envelope does not establish native SDK behavior. | Qualify text, reasoning and indexed tool-argument deltas; native response streams were not measured. | Native stream was unmeasured; normalize and test every supported shape or refuse it. |
| Immutable protocol | Preserve and validate any signature bytes required by the actual adapter; do not repair protocol fields by changing them. | Preserve and validate tool-call identifiers and types. | Preserve and validate thought signatures where the actual adapter uses them. |
| Reference following | Unmeasured: qualify each enabled route with synthetic references. | Qualify the selected route; another model does not establish its behavior. | Unmeasured: qualify each enabled route with synthetic references. |
| Passthrough | Require a vetted bridge to cover the actual body; native decision endpoints were unmeasured. | Require the same coverage; bridge coverage must be verified for each endpoint. | Require the same coverage; native endpoint behavior was unmeasured. |
| Provider cache | Structural cache markers do not prove the cached content is safe. | Stable references alone do not prove a stable full prefix or cache hit. | If explicit cached content is used, protect it before cache registration and account for any lookup request in its route budget. |

A cache or passthrough is conditional on its actual route and data flow; provider account retention remains separately unverified in [sensitive data lifecycle](sensitive-data-lifecycle.md).

## 4. Qualification

For each selected detection domain, declare categories, rule coverage and prefilter assumptions and qualify them as described in [detection boundaries](sensitive-data-lifecycle.md#3-detection-references-and-exposure-boundaries) and [checks](sensitive-data-lifecycle.md#6-build-debug-and-optimize-checks); a reference grammar alone does not establish detector coverage.

If this approach is selected, test every producer and every recipient independently with synthetic values in strings, keys, numeric leaves, encoded objects and result metadata. A foreign, malformed or erased reference must not produce another subject’s value; an unavailable mapping service must prevent the protected send. Qualify actual streaming envelopes and check that result withholding cannot be mistaken for a tool that never ran.

If qualifying exemptions, exercise valid and neighboring invalid origin, principal, request, carrier and operation proofs through the actual loader. If qualifying a backstop, inspect the effective process configuration and demonstrate a synthetic leak is refused by that process. If a child brief is involved, race child insertion with a subject fence and verify no raw brief is persisted. These are proposed checks, not results.

If qualifying reference protection, use adversarial escape/unescape round trips, concurrent registration and collision exhaustion; test erased, foreign and wrong-kind tokens, absent or ambiguous credentials, unavailable protection, malformed declarations, unsupported opaque parts and identifier-shaped immutable protocol values. Test bounded recursion, nullable arrays, numeric alternatives and customer-bearing error paths, with actual callback and hook activation. Compare adjacent provider-effective requests only under fixed configuration and context policy; stable tokens alone do not prove a cache hit.

If resource bounds or retries are used, measure representative and adversarial nesting, batch sizes, memory, contention, latency and churn. Test exhaustion, preserve refusal when traversal or freshness is incomplete, and do not inherit a reference-specific limit as an optimal value.

## 5. Worked example — one implementation under stated premises

Premises: a task accepts a contact field, sends text to an external model and has an authorized action that needs the original value. Admission registers the contact and sends a subject-scoped opaque reference; model-written arguments are validated as references, then an authorized executor resolves the value in a transient copy and validates the business schema. A withheld result after execution is reported as such and an uncertain effect is reconciled before any replay. The example provides no guarantee for untyped names or unsupported media.
