# Model gateway and reliability

Read this leaf only when a shared gateway is justified by shared routing, credential custody, admission or accounting, or when a model caller needs an explicit timeout, cancellation, retry or fallback policy. A direct adapter still needs its own applicable deadline and failure contract. The [model boundary](model-boundary.md) owns request and response fidelity; this leaf owns the conditional operational seam. The [execution host](../../agent-runtime-and-interaction/references/execution-host-and-lifecycle.md) owns run liveness, the [action boundary](action-and-tool-boundary.md) owns effects, and [cost accounting](../../agent-diagnostics-evaluation-and-resource-control/references/cost-accounting.md) owns reservation, settlement and reconciliation.

## Minimal path and decisions

If there is a gateway, document the actual ordered path: authenticate the caller; resolve the permitted route and policy; perform required privacy and attribution checks; if required, obtain an acknowledged reservation for a unique attempt; dispatch to the selected provider; relay the response; and settle reported or unknown usage against the same attempt. The order of route resolution, privacy and reservation is an implementation choice with dependencies: a refusal after an acknowledged reservation needs an accurate no-send settlement, while a refusal before reservation leaves a different record. Never move a privacy check ahead of the creation of a proof it consumes without redesigning and checking the proof flow. A proof-preserving reorder is proposed and requires implementation verification.

A failed reservation acknowledgement prevents dispatch under a reserve-before-send policy, including any shadow mode that still reserves. The receiver may have committed the reservation before its acknowledgement was lost: no send does not prove no row exists. Reconcile the pending record rather than fabricating an absent one. A reservation for attribution is not a monetary hold. Require a compatible receiver and credentials before enabling such a route; missing or rejected dependency must produce no provider send.

If settlement delivery is retried, freeze the payload and identity and use a receiver that recognizes an identical duplicate without overwriting a different or already settled outcome. Bound those dependency calls independently and within the caller's remaining deadline; do not treat a delivery retry as a new inference attempt.

| Choice | Pressure and contract |
|---|---|
| Direct bounded call | One route and caller can own credentials and failure handling; use the home chapter and the timeout rules below. |
| Shared gateway | Multiple callers need shared route admission, credential custody or attempt policy; inventory billable surfaces, named owners and failure dependencies. |
| One send per admitted attempt | Per-attempt accounting or an uncertain effect requires a trustworthy correspondence between the reservation and dispatch. Additional attempts need separate identities and accounting. |
| Retry or fallback | A retryable failure, sufficient remaining deadline, explicit caller policy and safe replay justify another attempt. Qualify fallback model capability, privacy and cost before use. |
| Shared quota | Multiple replicas share a provider account or scarce allowance; a local per-process counter cannot establish a fleet-wide bound. |

## Admission, routes and attempt integrity

If a gateway is used, its catalog maps each public alias to permitted deployments and credential references, limits and applicable pricing metadata. Keep the actual provider secret out of catalog text and bind it to the selected route; explicitly enumerate pass-through exceptions so one route cannot borrow another's credential. Qualify a new route's protocol, limits and final usage and price calculation before relying on it; a missing cache storage price is unknown, not a free call. Administrative model registrations may persist after a file edit and may not be included in a startup-only assertion. Without a per-request drift check, registrations can change between inventory checks; document the window and qualify the selected policy.

If legacy aliases are retained, mark their compatibility purpose and retire them through the owning migration; they are not a required new interface. If configuration overloads special sentinel strings and key names, reject collisions so an intended principal cannot be interpreted as an enforcement mode.

If a policy requires one generation send per reservation, remove or reject caller and key overrides that introduce hidden retries, fallbacks or fan-out; inspect live router settings rather than just a configuration file. At the actual synchronous and asynchronous send boundaries, bind a gateway-minted attempt identity to the concrete provider target, require the matching durable reservation acknowledgement, and refuse a second generation send under that attempt. Reject caller-supplied accounting stamps. A separate request, including an SDK retry or a fallback, needs a new attempt and may be billed independently; an attempt ID does not deduplicate separate requests. Where auxiliary provider operations exist, scope cache lookup and creation rules to registered targets and methods, with a separate bounded create budget, so a lookup does not consume the inference send or become a general bypass.

Inventory every billable route, including health checks, pass-through dispatchers and library helpers. A route that bypasses the admitting hook must be disabled, refused at the actual dispatch boundary, or brought under equivalent admission. Enumerated path refusals prove only those paths and the verified version; quarantining a missing stamp makes a gap visible but does not prevent unaccounted dispatch. If an optional shadow mode stamps ordinary violations and continues, report it as observation, not enforcement. Check both verdict and provider send count; a later one-send barrier does not mean the earlier guard refused. If an incompatible hook surface or special route cannot establish its required trust boundary, refuse that affected lane even when ordinary violations are shadowed.

Recorded design judgment: an internal-only caller premise does not by itself justify omitting per-key route restrictions or deployment-time retry and price checks. Assess the actual caller population and effective route controls before deciding which checks may be deferred; safety for an exposed gateway requires its own evidence.

For a pass-through route, capture the actual method, normalized path, query, selected upstream, request-local headers and body at a boundary that sees the real request. Check the allowlisted route and method, pinned model and target, credential binding, body shape and disallowed overrides before dispatch. If a library upgrade changes that boundary and validation cannot be established, close the lane rather than trusting inferred arguments. A failed call with unverifiable route or usage has unknown billability, not a certified zero. A privacy and quota ordering demonstrated for one route is not automatically the order for another.

## Deadlines, cancellation and stream failures

Name each timer by its scope: connect, pool, write and read phases; first-byte and between-chunk inactivity; quota and reservation wait; one provider attempt; and the host's whole-run deadline. Inspect request, deployment and router precedence for the installed versions: a phase timeout is not an absolute response deadline, and a stream that trickles can outlive every inactivity interval. Bound metadata, privacy, quota, reservation, cache work, connection, generation and retry sleep against a caller's remaining time when a finite end-to-end bound is required. A single absolute deadline spanning all phases is a proposed improvement, not a verified feature. Decide explicitly whether cache lookup failure or expiry aborts or permits uncached work. Propagate cancellation, close upstream iterators and account for in-flight attempts without claiming they were never billed.

A useful sizing check multiplies the maximum silent windows for the selected SDK attempts and allowed pre-commit replacement by the inactivity bound. It is not a worst-case bound: add connection and pool waits, retry backoff, hooks, cache operations, other calls and slow trickles, and enforce the absolute deadline independently. Select values using route-specific first-token and inter-chunk observations and the caller's failure budget; an incident on one model is not proof of a universal percentile or a justified exception.

For streaming, distinguish no first chunk, protocol-only chunks, and committed output. A policy may buffer protocol-empty chunks and replace the **model call only** after a timeout or connection-class failure before any content, tool delta, reasoning, usage or finish field has been committed, provided a new attempt is admitted and its possible charge is acceptable. Bound replacements and include SDK retries in that bound. After output is committed, report the partial stream and failure; do not silently restart it or replay the run and tools. Recovery of uncertain effects belongs to the action and host boundaries: reconcile before retry, replay only with verified idempotency for the same operation, and stop for manual reconciliation when the outcome cannot be established.

## Errors, retries and quotas

If quotas protect any route, inventory coverage and exclusions per effective route and account, including direct and fallback paths. Shared request and estimated-token admission is distinct from provider throttling; a quota on one decision route does not protect other model routes. Exercise covered and uncovered sends and quota-store failure, and report unprotected paths explicitly.

Publish stable machine-readable categories for invalid request or guard refusal, unavailable dependency, provider overload or rate limit, exhausted spend budget, incompatible gateway surface, and partial stream. A budget stop is a spend limit, not a provider outage or successful completion. Errors after headers are stream errors, not a new HTTP status. Qualify actual status and body mappings for each adapter; provider and SDK behavior can vary. Capture which layer emitted a refusal: a budget check before hooks can leave no guard log, while a later privacy refusal can leave an acknowledged reservation.

Make retry policy explicit by error class, attempt count and remaining deadline. A recommended, not established, policy is bounded exponential backoff with jitter and any valid retry hint for transient provider overload before output commit; treat an invalid request or guard refusal as terminal, a spend-limit refusal as terminal for that budget, and an unavailable reservation dependency as transient only after verifying no provider send. Disable or qualify opaque SDK retries when they would bypass that classifier; settings alone do not prove the caller stopped retrying. Recheck the installed SDK's retry directives, statuses, delays and actual gateway-request count. An alternative gateway can retry internally only if it mints and accounts for each send independently and respects replay, authority and output constraints.

A pre-qualified fallback wrapper was recommended in one implementation but not built. If fallback is chosen, make it an explicit new request with a qualified model and its own accounting; do not switch silently after committed output.

If a provider account is shared across replicas, an atomic shared quota can account for request and token estimates before dispatch using a unique admission identity and a bounded wait. Define whether the estimate is trusted, how long a charge persists and whether a racing or cancelled admission is refunded. Distinguish oversize input, current quota denial, wait deadline and store failure; if the next eligible time cannot fit, return the current denial rather than waiting beyond the budget. Check expiry at every loop boundary: an implementation may return its last quota result after a delayed sleep instead of a dedicated wait-timeout code. Provider quota is not a hard spend cap, and per-key rate isolation is a hypothesis to validate against a runaway caller, not an assumed fix.

## Causal lessons and operations

- **Premise:** capacity is constrained by provider-account quota. **Symptom:** throughput fails despite an apparently adequate local request count. **Cause and evidence status:** a route charged estimated units from request bytes; its workload sizing was not established. **Rule and reason:** measure the actual route's charged units, including byte-based estimates when applicable, and quota behavior under paced and burst load. **Check and expected evidence:** reconcile request bytes, admitted units, provider responses and throttles; mismatched accounting or an unmeasured route leaves capacity unknown. **Does not apply when:** no shared quota constrains that route.

- **Premise:** A gateway withholds headers until the first upstream chunk. **Symptom:** A call hangs without a stream error, or a role-only chunk is followed by silence. **Cause and evidence status:** A missing first chunk and protocol-only stall can both hide inactivity; route behavior is unmeasured. **Rule and reason:** Bound inactivity and distinguish protocol-only from committed output because the caller otherwise cannot decide whether a replacement would duplicate output. **Check and expected evidence:** With a fake upstream, withhold the first byte, emit a role-only chunk then stall, emit content then stall, stall twice, and trickle steadily; assert request counts, cancellation and no replacement after commit. **Does not apply when:** The caller never streams; it still needs a non-stream deadline.
- **Premise:** A shared gateway reserves attempts before send. **Symptom:** Calls fail with an unavailable reservation dependency, yet a pending row appears. **Cause and evidence status:** A lost acknowledgement can follow a successful commit; failure to confirm a reservation must stop dispatch. **Rule and reason:** Separate no-dispatch evidence from no-record evidence and reconcile pending rows. **Check and expected evidence:** Drop the acknowledgement after durable commit and assert zero provider sends plus a recoverable pending reservation. **Does not apply when:** There is no pre-send reservation policy.
- **Premise:** Provider inference performs auxiliary HTTP work. **Symptom:** A legitimate generation is refused as a second send. **Cause and evidence status:** One implementation counted cache lookup against its sole generation budget. **Rule and reason:** Separate restricted auxiliary operation budgets from generation because they have different effects and charges. **Check and expected evidence:** A registered lookup and bounded create precede one generation; an unrelated target or second generation is refused. **Does not apply when:** The provider path makes no auxiliary operations.
- **Premise:** A gateway route is slower than another. **Symptom:** Long first-token time looks like an outage. **Cause and evidence status:** a gateway-to-provider span can include queueing, cache, connection and provider work; a single span does not distinguish them. **Rule and reason:** Compare phase spans before assigning cause or changing timeouts. **Check and expected evidence:** Record selected route, first-token time, inter-chunk gaps, cache operations and upstream spans; an absent span leaves the cause undetermined. **Does not apply when:** The diagnosis already has authoritative phase evidence.
- **Premise:** A library upgrade changes hook or route internals. **Symptom:** Boot, first request or only one pass-through lane fails, or a spend record lacks a stamp. **Cause and evidence status:** Hooks can depend on undocumented surfaces, and assertions can disappear in optimized execution; coverage of each wrapper needs verification. **Rule and reason:** Validate actual surfaces and fail the affected lane closed; version pins or a clean log alone cannot establish complete coverage. **Check and expected evidence:** Change a signature or route layout in a fixture, exercise both loader orders and assert refusal before send and exactly-once installation. **Does not apply when:** No custom integration depends on those surfaces.

If hooks patch vendored code, make installation idempotent even when a loader executes the same file under another module identity. Keep shared attempt state outside independently reloaded modules, assert or explicitly validate the actual supported interfaces, and record whether a drift fails boot, the first request or a specific lane. Prefer explicit raising checks where optimized execution can remove assertions. Unchecked variadic wrappers can drift despite other signature checks; a stronger drift fixture is proposed, not verified. A fake-provider harness and unit checks cover only enumerated cases; an intended complete black-box suite is not evidence that such a suite exists.

An apparently empty callback can install a patch during import, so inspect the actual cost and logging path when establishing hook order. A first-request validation that caches success covers only the objects it actually inspects and does not establish continuous drift detection.

For a missing-credential symptom, inspect selected configuration and route-to-credential binding first, then value-silent credential availability, mount and authentication. Do not print secrets or infer a single cause from the error. For each upgrade or route change, record the actual artifact, effective settings and observed route separately from source and historical reports; delivery evidence belongs to [delivery and activation evidence](../../agent-configuration-and-delivery/references/delivery-and-activation-evidence.md).

Credential refresh can also add per-call latency when a helper is rebuilt for each request. Measure that phase on the target route before attributing delay to the provider; a shared cache with appropriate synchronization is one conditional remedy, not an assumed bottleneck.

If sizing capacity, compare concurrent bursts and paced load on the actual route with gateway and upstream spans; a short sample without rate-limit responses does not establish sustained capacity or the cause of latency. If measured burst concurrency contributes to latency on the actual route, compare paced or jittered fan-out against the burst under the same workload and correctness constraints; a short observation does not establish the underlying cause or sustained capacity. For a judgment that needs shared context, compare one sufficiently contextual call with a split design before assuming shorter inputs lower latency; a few route-specific samples do not establish general latency scaling.

## Build, debug and optimize checks

1. **If a gateway exists:** Inventory routes, credentials, effective catalog and all hook bypasses. Exercise each allowed and refused path and compare guard verdict with provider send count. An unenumerated billable route remains an exposure, not a passed admission check.
2. **If per-attempt reservation is required:** Inject missing and rejected receiver credentials, lost acknowledgement and duplicate settlement; expect no send without the exact acknowledgement and truthful pending or settled status. In shadow, verify the same required reservation gate.
3. **If retry, streaming or cancellation is enabled:** Drive the real caller chain against a fake upstream with the stall shapes above, a slow trickle, repeated failures and cancellation. Count sends and reservations, verify deadline scope and confirm that committed output is not replayed. SDK retries and replacement requests must be visible as distinct attempts.
4. **If a shared quota is used:** Exercise concurrent replicas, oversize requests, exhausted wait before entry, store timeout at the deadline, delayed sleep, impossible next expiry, store failure and an admission racing cancellation. Expect the documented category and no unsupported refund claim.
5. **If patched hooks are used:** Test actual versioned surfaces and both loading orders; verify affected-lane refusal on drift and exactly-once cost correction. Review the coverage and failure mode of each check, including optimized execution; missing tests are an evidence gap, not a pass.
6. **If optimizing latency or cost:** First separate first-token, network, gateway, cache and provider spans, then size timeout and retry budgets against the host deadline. Compare route-qualified final usage and price evidence through [cost accounting](../../agent-diagnostics-evaluation-and-resource-control/references/cost-accounting.md); a streamed cost header is provisional.

Keep the distinction between a source-read implementation, an observed route, a chosen policy and a proposed improvement in every diagnostic claim. An unmeasured current deployment remains unverified; a clean log cannot prove all routes or all calls were covered.

## Worked example — one implementation under stated premises

Premises: several services share one model gateway, each billable generation requires a durable attribution reservation, and the caller streams output. The gateway authenticates the caller, validates its permitted route, receives an exact reservation acknowledgement and admits one generation send under the minted attempt ID. The caller buffers a protocol-only chunk; a connection failure before committed content ends that attempt and, if the caller's remaining deadline and policy permit, starts one separately reserved model-only attempt. After visible text, a failure is returned as partial output. The system reconciles the first attempt's unknown usage rather than reporting zero; no tool effect is replayed. A fake-upstream fixture can verify these contracts, but does not by itself establish live provider behavior.
