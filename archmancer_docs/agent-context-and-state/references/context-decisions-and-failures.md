# Context and memory decision seams

Read this leaf when choosing history reduction or memory extraction, or investigating a continuity failure. The [home chapter](context-and-state-management.md) defines the common request and checkpoint contracts; [durable memory](durable-memory.md) owns admission and forgetting.

## Conditional decisions and rejected shortcuts

| Premise | Choice and rationale | Evidence or failure check |
|---|---|---|
| A task must survive a side question or interruption | Keep a durable outcome, completion criteria and active constraints, with a separately revisable plan. A static rule telling the model to return to the topic was rejected as a substitute: it has no durable state or correction semantics. | Interrupt, reload, compact and resume; inspect whether the actual active objective and cancellation survive. A hand-authored summary alone does not prove the compactor. |
| A task needs a plan | Permit paired goal and plan updates where needed, with explicit atomicity, validation and receipts; revise the active plan when evidence shows its route cannot achieve the goal. For an uncomplicated task, reject a universal plan-first restriction: it can block independent useful actions whose arguments are already known. | Force a failed plan update, a route failure and an independent action; inspect the revised plan and resulting goal. |
| A task can exceed a window mid-run | Check the next composed request before each model call; end-of-run maintenance alone cannot prevent a large intermediate result from overflowing. Schedule optional end-of-run work after visible completion only when it does not delay a required durability fence. | Grow a tool result between calls; verify the selected reduction or explicit overflow response before dispatch. |
| A model summary must preserve protected state | Reject a probabilistic judge that can override the deterministic guard without evidence; a plausible score cannot prove required preservation. Add a model judge only as an additional measured quality signal. | Try a fabricated identifier, an unsupported retirement and a qualifier present only in earlier evidence. The guard or independent carry must retain the requirement; qualifier-loss risk is a hypothesis to measure, not an observed rate for this reducer. |
| Two outputs must appear in one model response | Treat a mixed update-and-final response as unqualified until the exact adapter and output contract pass their declared acceptance gates. A route that fails before producing a usable response supplies no behavioral result. Do not generalize one route's result to all providers. | Qualify the exact adapter and output contract with actual mixed emissions under a separately authorized, frozen test. |
| Memory extraction follows compaction | Trigger-on-checkpoint is economical when sufficient, but misses short sessions and the unconsumed tail; periodic extraction was rejected under a cost/complexity judgment, not a measured universal failure. An explicit save may cover a different need. | Measure missed eligible facts, short sessions, tail coverage and complete cost before choosing periodic, save-triggered or combined paths; deferred cache savings are unmeasured. |
| Memory requests may not fit | Shrink optional advisory context and recount. If the indispensable extraction request still cannot fit, return a controlled failure with its stage and coverage impact; never disguise it as a successful empty extraction or a routine admission exclusion. | Force both fit failures and inspect inline transaction rollback versus the background job's explicit failure/notification contract. |
| A retained prefix is edited under pressure | If reuse matters, freeze one eligible selection per checkpoint epoch, preserve tool-call structure and the latest successful goal receipt, and replay only stable unambiguous IDs. Reset when the checkpoint changes. No eligible edit means no fabricated edit record. | Repeat below and above pressure; inject duplicate or absent IDs, new receipts and changed checkpoint; expect no destructive raw-history mutation. |
| Old observations consume the next request but some detail may be lost | Recorded design judgment: first clear or trim eligible older material to stretch the run before generating a new continuation; protect active constraints, current receipts and complete tool pairs. Clearing avoids continuation generation but loses detail and can invalidate affected history-cache boundaries; a frozen selection can avoid repeated edit-induced rewrites within its valid epoch. It does not preserve facts for later extraction unless another authorized source path retains and reads them. | Compare retained facts, full projected size, changed prefix boundaries and subsequent extraction coverage; an indispensable fact removed without an independent admitted representation falsifies the choice. |
| Interactive work repeatedly reaches inline reduction | Recorded design judgment: a pre-call compaction path protects fit but alone leaves the user paying every reduction pause. Where that delay warrants the lifecycle cost, run the same compactor opportunistically after visible completion, preserving the required durability fence before completion. Background preparation adds capacity contention, parent-version fencing and exact-operation joining; unfinished preparation may still delay the next request. | Observe answer-to-completion delay and next-request wait separately; grow an intermediate result, race a newer checkpoint against background completion, and join only matching work. Do not infer that background scheduling removed latency. |

## Failure paths and boundaries

**Premise:** background reduction can overlap a new run. **Symptom:** an older result is installed over a newer checkpoint. **Cause and evidence status:** an asynchronous worker may finish after its parent changes; source described parent comparison and single-flight as one design. **Rule and reason:** adopt only a valid advancing result from the expected parent and current owner, or discard it; join, cancel or run inline according to the declared liveness policy. **Check and expected evidence:** interleave two parents and a failed or unreadable job; no stale result becomes authoritative. **Does not apply when:** reduction is synchronous and no concurrent owner exists.

**Premise:** read or write state spans multiple processes. **Symptom:** concurrent first opens bind different owners, or a stale finalizer resurrects a context. **Cause and evidence status:** a read-then-create sequence has a race; source marks atomic create-if-absent as a design requirement. **Rule and reason:** bind scope atomically, reconcile ambiguous open via a trusted read and current attempt, and compare the expected parent/version on commit. **Check and expected evidence:** race two owner claims and lose the first acknowledgment; only the authorized owner exists, and replay or refusal is explicit. **Does not apply when:** ownership is established immutably before any concurrent access.

**Premise:** a snapshot or continuation is used as later input. **Symptom:** model-generated language or a prior per-run snapshot is treated as newly observed evidence. **Cause and evidence status:** inconsistent host-owned fields and provenance filtering can promote generated text into evidence; the stronger exclusion requires verification. **Rule and reason:** preserve distinct writer, capture time and authority, and reject generated rows as source evidence under the stronger provenance contract. A current result can update the snapshot; it cannot change the source's evidence time. **Check and expected evidence:** replay an old snapshot next to a correction and attempt to cite its generated text; the correction wins and the generated citation is refused. **Does not apply when:** the call has no persisted or generated context.

**Premise:** memory jobs accumulate or fail. **Symptom:** new facts silently stop being retained even though checkpoints succeed. **Cause and evidence status:** admission accounting for open and failed payloads can exclude later work. **Rule and reason:** bound and observe backlog per authorized scope, account for retained failed payloads, and distinguish deferred, excluded and failed outcomes. **Check and expected evidence:** fill the backlog, inspect receipts and recover or explicitly exclude work; do not claim full extraction coverage. **Does not apply when:** all saves are synchronous and bounded without a job backlog.

**Premise:** retention or recall is optimized. **Symptom:** compact context looks smaller but loses qualifiers or omits crucial old evidence. **Cause and evidence status:** numeric sizing and previous comparisons are workload-specific, and qualifier loss is a hypothesis rather than a measured rate. **Rule and reason:** evaluate required-fact retention, fit, latency, cost and wrong-subject exposure together, using representative workload and held-out examples. **Check and expected evidence:** plant facts and qualifiers before repeated real reductions and inspect final answers and provenance. **Does not apply when:** the application accepts loss of all earlier context.

If classification or semantic recall is enabled, version its definition and embedding profile, measure candidate omissions, and compare the source pool version at commit. Do not silently declare a partial advisory list complete. Retire or retain forget barriers according to the erasure contract; a storage cleanup must not enable old evidence to revive.

If classification fails, retain an explicit unclassified status visible to downstream consumers rather than a negative score or completed classification; commit a score and definition version only on success. Inject classifier failure and inspect the row and downstream projection; they remain unclassified even if the encompassing job continues.

## Further decision boundaries

| Premise | Previously deferred or rejected route | Evidence to reopen |
|---|---|---|
| Similarity-based memory recall exists | A fixed score floor, lexical fusion, reranking, query rewriting, reconfirmation, second deduplication and additional profile weighting were each deferred, rejected on limited screens or left as hypotheses; these are different evidence states, not universal failures. | A representative, paired recall evaluation with wrong-subject and forbidden results, quality, latency and total cost. |
| Memory writing exists | Periodic or episodic extraction, a separate search tool, richer temporal graph, title augmentation and expiring a reversible mapping add coverage or capability at operational cost; they were not adopted as defaults. | Demonstrated coverage or product need, with ownership, retention and forget behavior specified. Do not expire mappings still needed by retained data. |
| Several pressure triggers are enabled | Fixed soft, edit and hard ratios are an example, not portable thresholds. Validate the order and range for whichever mechanisms coexist so one trigger does not make another unreachable. | Real fit, retention and latency behavior on the target workload; omit ordering constraints for disabled mechanisms. |

## Worked example — one implementation under stated premises

Premises X: a persisted assistant uses a named user-role snapshot because its particular adapter relocates system messages; that role assignment is a transport choice, not user authority. Its edit policy retains a chosen recent window and counts parallel results individually, while leaving the latest goal receipt intact. A background checkpoint may pin the latest input locally, then release that pin on a later execution; the bounded quotation archive remains a different artifact. A legacy whole-turn checkpoint writer can coexist during migration only with its weaker concurrency contract made explicit.
