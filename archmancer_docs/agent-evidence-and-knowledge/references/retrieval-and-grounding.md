# Retrieval and grounding

Read this leaf only when a task needs to discover or select evidence from more than a known direct read, or when a retrieval result must be handed to an agent. Source visibility, version and grounding authority belong to the [home chapter](evidence-and-knowledge-access.md); [flow 5](../../agent-system-engineering/references/system-flows.md#5-knowledge-grounded-answer) shows the handoff across components.

## Scoped retrieval

The caller provides one or more focused needs and verified authority; it does not allow the model to select a principal or expand visibility. A need should preserve its subject, relation and constraints. Search within authorized, eligible content, then recheck access and revision when fetching bodies. A result can include source identity, version, passage, locator and selection metadata; do not mistake a generated card or snippet for the canonical evidence unless the source contract makes it authoritative. If links or neighbours are offered, apply the same checks to every reached item; a hidden target must not disclose its existence through a distinguishable link result.

When a turn requires a consistent view across selection and body reads, use a snapshot or version-qualified identity and conditional read. If the selected version is unavailable or has changed, restart within the chosen bound or return a version conflict or unavailable status. Do not combine the hit for one revision with a newer body's citation. If a backend cannot provide this capability, describe the weaker consistency and avoid a claim of exact reproduction.

If batch reads or neighbour expansion are supported, declare response order, per-item missing or already-read status and duplicate handling; for an item requested both explicitly and as a neighbour, choose and test which relation wins. Include truncation when a link or neighbour limit omits visible results.

## Result contract

For each need return its own status, such as `matched`, `no_hits`, `unavailable` or `invalid`, plus relevant source identities and versions. Return delivered passages, omissions with reasons, and safe errors independently. A partial batch can contain both usable evidence and an unavailable need. A successful empty list means only that this lookup delivered no hits under its scope, query and limits. A retrieval error, timeout, unreadable candidate, filtered source and exhausted budget are not a verified absence. Preserve cancellation as cancellation.

When the query dependency fails, propagate an unavailable outcome to the affected need with a safe error; preserve independent successful needs. A retrieval failure is distinct from failure of the outer agent run or of its relay transport: an outer failure may prevent any retrieval result from reaching the caller, and a caller timeout can occur after remote work completed. Report the observed layer and leave the remote outcome unknown until reconciled; do not turn a missing relay response into no hits. Inject a lookup failure, an outer-run failure and a relay timeout after remote completion, and check their separate outcomes and any recoverable receipt. Follow [durable recovery](../../agent-runtime-and-interaction/references/durable-execution-and-recovery.md#4-intent-reconciliation-and-recovery-paths) when dispatched work needs reconciliation.

An illustrative handoff has `needs: [{query, status, matched_sources}]`, `sources: [{source_id, revision, locator, body}]`, `omissions: [{source_id, reason}]` and `errors: [{need, safe_code}]`. Correlate it to the actual call; avoid raw exception text that can disclose internal data. Distinguish invalid input from an unavailable source. A shared action for all-failed and successful empty searches can conceal unavailability; a distinct unavailable action is a proposed design, not a verified fix. Consumers of that shape must inspect per-need status and errors.

State coverage explicitly. If source selection occurs before deduplication and budgeting, skipped bodies can leave unused capacity without refill; a single body larger than the allowed budget might never be deliverable. Report that limitation and offer only operations that actually exist. Whole bodies or complete relevant spans preserve qualifiers at a context cost; truncation and projection need explicit loss policy. With greedy skip-and-continue, a larger budget can admit an earlier body and displace a later one, so test every candidate budget with required-fact controls.

## Ranking and selection

| Need or pressure | Candidate mechanism | What to qualify |
|---|---|---|
| A known source and exact key | Direct read or SQL predicate | Authority, version, missing versus unavailable. |
| Exact codes or identifiers | Literal search | Escaping, normalization, in-token matches and source scope. An exact numeric or code literal embedded in a larger token can be missed by embedding and token-level lexical retrieval although its containing unit exists; test it per lane against a literal-substring lane (see Checks; one small measured corpus, no claim about tables or thresholds as a class). |
| Semantic variation | Semantic similarity | Query/document encoder compatibility, recall and irrelevant-neighbour behavior. |
| Different needs compete for a limited handoff | Interleave ranked results or another explicit allocation | Required-fact retention for each need, duplicates and omissions. |
| Measured relevance problem | Lexical/semantic fusion or reranking | Recall, false-no-match, degradation, cost and latency against the same baseline. |
| Measured context problem | Structured excerpts or pruning | Independently adjudicated loss of conditions and qualifiers, failure fallback and budget. |

A score can encode rank rather than relevance, and nearest neighbours can be unrelated; preserve the returned order if scores are informational. A failed reranker should return an explicit degraded status and usable baseline order if policy permits, not an unsupported no-match. Model stages and indexes are choices, not mandatory steps; evaluate candidate pool and source limits on the target corpus. A reranker can improve a no-match signal at latency and recall cost; a programmatic retrieval agent can miss joint latency and provenance gates. A projection can drop answer-bearing qualifiers, so evaluate these trade-offs on the target workload rather than assuming average compression proves safety.

Observations on a different hybrid path establish neither current recall nor an optimal candidate or source cap. On the target corpus compare recall and required-fact retention across candidate caps with the same scoped gold set, alongside latency and cost; a cap that drops required evidence fails the chosen fact-loss gate. Omit cap tuning when a known direct read satisfies the need.

## Retrieval family trade-offs

The following reach order is a recorded design judgment to qualify on the target workload, not a measured ranking of all retrieval systems. Compare build and maintenance work, caller-visible latency, operating cost, source recall, delivered precision and the evidence actually admitted to the model; test growing corpora and distracting near-matches rather than inferring quality from an index type.

| Need and lever | Gain, cost and reach rule |
|---|---|
| Known source — exact read | Read the authoritative file, row or passage first: it avoids ranking loss and index construction, but requires the right locator, scoped source integration and version handling; source I/O and large bodies still cost latency and context. A keyed read does not acquire a top-k recall ceiling merely because the corpus grows, but cannot discover an unknown source. Give the model the scoped source data and provenance. |
| Fast local discovery — plain hybrid chunk retrieval | Lexical plus semantic search is a relatively small prototype and query path compared with extracted graphs or iterative model search, but still owns parsing, splitting, embedding and index refresh. The model receives a bounded set of possibly disconnected chunks; growing candidate competition and missing neighbouring conditions can hurt precision or recall, with no universal degradation rate. Use it as a local-fact baseline, keep exact identifiers searchable and preserve a route to read coherent evidence before widening the pool. |
| Relations or corpus-wide themes — graph-based retrieval | Extracted entities and relations, and optionally community summaries, can connect evidence that flat chunks separate; the model may receive triples, descriptions, summaries and source passages. Pay extraction and identity-resolution work, fidelity checks, update/deletion propagation and retrieval-flow complexity only when relation or global-query failures justify them. Wrong or missing edges can distort precision and recall; summaries can lose detail. Precomputed local traversal can be fast, while global synthesis can add many calls: qualify query latency and growing-corpus behaviour by the actual algorithm, not by the presence of a graph. |
| An unresolved question has new leads — agentic search | Iterative search, exact matching and file or document reads can pursue evidence outside the initial top-k without requiring a semantic index. The implementation still needs scoped tools, navigation and stopping rules; repeated scans and model rounds add variable operating cost and latency paid by the waiting user, increasingly so on broad corpora. The model receives successive observations and selected passages, not guaranteed exhaustive coverage. Prefer this for justified unresolved needs or latency-tolerant investigations; each additional round should target an unanswered slot, derive from seen evidence and expect a new source or span. Stop with an explicit gap when the frontier or budget is exhausted. |
| Coherent evidence with a quick entry point — linked wiki plus hybrid discovery | A linked document wiki with a hybrid search layer can locate relevant documents quickly, then expose complete relevant bodies and bounded links or neighbours instead of restarting exploration across the entire corpus. Cards route reads; bodies support claims. This recorded design judgment trades link/card upkeep, source alignment, index freshness and extra scoped reads for coherent evidence and less open-ended exploration; its comparative benefit remains to be measured. Growing corpora can still create missed entry points, stale links and truncated frontiers. Use it when flat chunks lose relationships but a fully extracted entity graph is not justified; expand only for unresolved evidence, under the same visibility and version checks. |
| Relevant evidence is buried in the candidate pool — reranking | Reorder a qualified candidate pool when relevance errors justify the extra compute or model call; a calibrated verdict can reduce pointless follow-up, but false negatives, unavailable ranking and additional user latency or operator spend remain costs. A reranker cannot recover a source outside its supplied pool, and snippets can omit the very qualifier needed to rank it. Check pool recall first, retain an explicit degraded baseline when permitted, and do not pay for semantic ranking when a scoped exact lookup answers the need. |
| Evidence competes for the model window — budget and projection | Deduplicate and allocate complete useful spans across needs before applying lossy projection. Smaller admitted material can reduce noise and repeated input cost, but projection can discard exceptions and another selection call or re-read adds user latency and operator cost. If projection rewrites previously replayed evidence, affected cached-prefix boundaries may become unusable while earlier unchanged registered boundaries can remain reusable; projecting a newly appended result has a different cache effect. Compare effective request boundaries, cache-read and creation charges, selection work and caller-visible latency rather than treating fewer input tokens as lower total cost. Compare the exact delivered context and answer against original required facts; more candidates or a larger budget need not preserve the same sources under greedy allocation. Keep omission reasons and a full-source recovery path where available, and refuse a completeness claim that the admitted evidence cannot support. |

Implement exact access as a read tool function taking an authorized locator and returning source identity, version and body. For hybrid retrieval, write an ingestion job that parses and splits sources, builds lexical and vector indexes and refreshes them on source changes, then a search function that fuses candidates. For graph retrieval, write an entity/relation extraction job, graph store and traversal query function; keep every derived relation linked to source evidence. Agentic search is a bounded search/read loop with frontier state and stop checks. A linked wiki uses a document store, maintained links, hybrid discovery and a body-read tool with bounded traversal. Put a reranker function after candidate generation and before selection; put deduplication, budget allocation and any lossy projection in the tool-result selection function, retaining source identity, omissions and a full-source read path where available. These are alternative compositions, not a requirement to install every retrieval family.

## Causal lessons

**Premise:** a selector cuts bodies after retrieval. **Symptom:** an answer omits an exception although the returned source contained it. **Cause and evidence status:** projection can omit spans needed for an answer; recovery and comparative quality must be verified on the target corpus. **Rule and reason:** preserve access to the complete source or qualify projection against independent planted facts, because a repeated search cannot reliably repair an omitted span. **Check and expected evidence:** place qualifiers in adjacent blocks and compare delivered evidence and final claims against the original source. **Does not apply when:** the complete authoritative passage already reaches the agent.

**Premise:** a model follows instructions attached to retrieved evidence. **Symptom:** it fills an uncovered specific value from general knowledge. **Cause and evidence status:** wording and placement can have model- and route-specific effects; a universal prompt is unverified. **Rule and reason:** state the evidence-basis rule close to its relevant result and test the complete request, because wording and placement are part of the effective carrier. **Check and expected evidence:** compare present, scoped-absence, wholly missing and distractor cases with an unsupported-value negative control; report each failure and model route. **Does not apply when:** the task needs only general conceptual explanation and makes no case-specific claim. When separating role reasoning from case-specific claims, compare any explicit permission to use general knowledge against the same evidence rule without that permission, and compare valid placements of the same rule with a neutral-placement control. Limited reported measurements found more unsupported values with such a permission and better gap handling with a rule-bearing tail, while a neutral tail did not help; these findings do not establish universal wording or placement.

**Premise:** several searches run concurrently. **Symptom:** one timeout turns a partially grounded answer into a claim that nothing exists. **Cause and evidence status:** an aggregate action can conflate no hits with all failures even when per-need errors exist. **Rule and reason:** surface per-need statuses and keep successful evidence; a failure is not a negative search result. **Check and expected evidence:** force one need to fail and another to succeed, then fail all; no failed need is described as absent. **Does not apply when:** every source was successfully and exhaustively checked within a clearly defined scope.

|---|---|---|---|

| Selection or answer quality | Qualify case-level behavior on the selected route. | Qualify wording placement on the selected route. | Qualify gap-filling on the selected route. |

See [model boundary](../../agent-harness-model-and-tools/references/model-boundary.md) for transport and [prompt cache layout](../../agent-context-and-state/references/prompt-cache-layout.md) for provider-effective request comparison. An effort comparison without an identified model cannot establish a general latency win; measure the target route. No provider brand establishes a retrieval-quality guarantee.

If a query, ingest or optional polish calls a remote dependency, qualify the application wrapper, underlying SDK and any gateway retry policies separately on the actual route. Count transport attempts and measure per-attempt timeout and outer deadline under a controlled retryable failure; no wrapper retry loop alone proves a single attempt or bounds total elapsed time. Compare the observed caller-visible query outcome, ingest job disposition and polish fallback with their owning contracts. Wrapper recovery evidence alone does not qualify SDK behavior.

## Checks

- **Build:** enumerate source, query and body-read interfaces and their authorized scopes, versions, ordering and per-need status. Check mixed success, all failure, malformed data, timeout and cancellation separately.
- **If sources mutate:** inject promotion between search and read; a consistent-turn contract returns the selected revision or a conflict, never a substituted revision.
- **If ranking is used:** freeze a versioned corpus and query set with scoped gold units and allowed alternatives. Report recall, hit rate and reciprocal rank separately; validate label provenance and distinguish retrieval acceptance from answer correctness. A deterministic unsupported answer must fail the scorer. When answers depend on exact figures or codes, also build a corpus-derived needle set (each exact figure plus its containing unit, gold by containment), run it per retrieval lane at the candidate cap actually used, and compare with a literal-substring lane; the recorded measurement is one small corpus, covers no table or threshold class, and shows retrieval coverage, not answer fidelity.
- **If pruning is used:** compare to the same unpruned retrieval, plant answer-changing controls and adjudicate lost facts; freeze hard loss, latency and cost gates before a model experiment. A model or judge failure is not silently scored as absence.
- **Debug:** verify the asked fact exists in the served source, then trace candidate selection, hydration, context admission and answer. Check exact body, source revision and omitted reasons before tuning the retriever.
- **If optimizing:** capture stage timings under comparable warm and cold conditions and actual concurrency; optimize the observed bottleneck. A local cancellation or timeout does not prove remote work stopped.
- **If reusing historical latency evidence:** identify the exact measured route and stages. A serial embedding-plus-hybrid-fusion measurement describes that path, not a different collector or its concurrency percentile; instrument the actual selected path and verify stage boundaries before setting a budget.

## Worked example — one implementation under stated premises

Premises: an assistant answers from an existing search API with immutable document versions, a limited context window and two independent needs. It searches both needs under caller authority, reads the best authorized version-qualified passages, and returns each need's status along with source locators. One search times out; the answer uses the other passage and states that the second need could not be checked. A later query can retry the unavailable need only if the product supplies that operation.
